## 實際完成

**規則式複盤服務（反事實比較）**

- `app/Domain/Game/Simulation/BattleSimulator.php`：把原本只能從關卡開局跑的迴圈拆成 `play()`，新增 `continueFrom()`，可以從任意已存在的局面接著模擬到結束，行為與 `run()`／`game:simulate` 完全共用同一段結算邏輯。
- `app/Services/Game/CounterfactualComparator.php`（新增）：給定一局**已結束**的對局與某一筆行動序號，重建「那一手之前」的局面（第一筆用 seed＋凍結牌組重開局，之後每一筆用上一筆的 `state_after`，做法與既有 `RunService::retry()` 相同），套用一個不同的行動，再交給 `planner`／`greedy` 策略接手打完剩下的回合。只讀 `Run`／`RunAction`，不寫入任何東西。
- `app/Http/Controllers/Api/V1/CounterfactualController.php`＋新路由 `POST /api/v1/runs/{run}/counterfactual`：擁有者隔離（不是自己的局一律 404）、局面未結束回 409 `run_in_progress`、換上去的行動不合法或指定的是揭牌回 422（新增 `InvalidActionException::sequenceNotReplayable()`）。這個唯讀計算沿用既有 `ReplayController` 在 P03 就寫好的定位：「這是 P07 複盤與反事實比較的唯一輸入」。
- 前端：`resources/js/game.ts` 新增 `fetchCounterfactual()`／`counterfactualText()`；`App.vue` 在戰報的完整行動紀錄裡，每一筆出牌旁邊都能按「如果這回合改蓄勢，結果會怎樣？」，即時顯示模擬出的另一種結局與回合數，並註明是否真的和實際不一樣。反事實只影響顯示，換一局就清空，不改到任何已存的紀錄。

## 規格偏差與決策

- 反事實比較預設用 `planner` 策略接手續局，可帶 `strategy=greedy` 改用貪心策略；沒有做「完全照抄玩家原本的打法」這種選項，因為那已經是「重放實際那一局」，不是「如果換一個選擇」。
- 前端只在戰報頁提供「换成蓄勢」這一種一鍵比較，沒有做「任選一張手牌」的完整下拉選單：規則式服務本身支援任意合法的替代行動（後端測試也驗證了換成實際打出的那一張牌），但完整的手牌選擇 UI 需要额外重建「那個當下的手牌」再處理留牌／換牌等邊界情況，超出本階段要交付的最小可驗收範圍；服務介面已經留了 `card_id` 參數，之後要擴充不需要改 API 形狀。
- 「兩套獨立結局」的文案／畫面／音效判定為 P04～P06 已完成，本階段沒有重做，只在驗收表列出確認方式。

## P10-0.1 量測修正（2026-10-05）

P10-0 的第三項指標有兩個語意錯誤，P10-0.1 只修正量測，不改任何關卡、技能、城市意圖、`config/game.php` 或 `rules_version 3.1.0`。

**錯誤一：「失誤」可能根本不是失誤。** P10-0 的 `planner-one-mistake` 直接出 planner 排名第二的行動。排名第二經常只是**同招同系的另一張實體牌**（例如最佳是 `open-chill-1`、第二是 `open-chill-2`），或是和最佳**同分**的另一個行動。這兩種都沒有讓玩家變差，卻被算成「犯了一次錯仍通關」，把恢復率灌高。

**錯誤二：恢復率不是恢復率。** P10-0 用 `planner-one-mistake` 的無條件總勝率當第三項，分母包含 planner 本來就會輸的局。

**修正後：**

- 失誤必須與最佳行動**語義不同**（簽章 `type|skill_id|target|fixed`，不看 `card_id`），而且 planner 分數**嚴格低於**最佳。依 planner 排名往下找第一個符合者；窗口裡找不到就照 planner 出牌並記 `no_eligible_mistake`，不硬塞假失誤。窗口在對局結束前沒出現則記 `window_not_reached`。
- 逐局狀態改由模擬器在每局開始呼叫 `beginGame()` 重置（新介面 `InstrumentedStrategy`），不再用「回合沒前進」猜新局。
- `one_mistake_recovery_rate` 改為**同（關卡, 牌組, 情境, seed）配對**：分母 = planner 原本通關**且**真的注入失誤的局（`eligible_mistake_games`），分子 = 其中注入失誤後仍通關的局（`recoveries_after_mistake`），逐關合併計算。
- 第三項語意改變，`INDEX_VERSION` 由 `p10-di-1` 升為 **`p10-di-2`**；`rules_version` 仍是 `3.1.0`。
- `game:difficulty-report` 拒絕未知 `--strategy`、未知 `--level`、`--seeds` < 1 或非整數、未知 `--suite`，一律回傳 exit 2 且不寫任何報告檔。修正前 `--strategy=typo` 會 exit 0 並產生空報告。
- 新增 `--mistakes-csv=`：逐局串流寫出失誤紀錄（回合、最佳／失誤行動的語義簽章、實體牌、分數、score delta、舊版排名第二是否同語義／同分）。逐格 JSON／CSV 增加 `planner_baseline_wins`、`mistakes_injected`、`eligible_mistake_games`、`recoveries_after_mistake`、`no_eligible_mistake_games`、`window_not_reached_games`、`legacy_second_same_semantics`、`legacy_second_tied`、`recovery_rate`、`avg_finite_score_delta`、`min_finite_score_delta`、`mistakes_skipping_a_winning_move`、`mistake_turns`。逐局紀錄不放進 JSON：完整矩陣 81,000 局全留在記憶體會超過 PHP 128 MB 上限（第一次重跑實際在第 4 關因此中止）。

### 修正前的「失誤」有多少其實不是失誤（full，27 情境 × 300 seed）

每一局都到達了窗口，也都找得到合格失誤（`no_eligible_mistake` 與 `window_not_reached` 全為 0）。下表是在同一個窗口裡，P10-0 會選的「排名第二」與最佳行動的關係：

### 量測定義

- **情境標籤** `w?h?l?`：水／熱／土地依序，`-` = −0.15、`0` = 中性、`+` = +0.15（`config('game.scenario.modifier_limit')`）。quick：`w0h0l0`、`w-h-l-`、`w+h+l+`，以及單一系別取 `-`／`+` 的 6 組；full：27 組完整排列。
- **牌組**：第 1、2 關 `starter`；第 3、4 關 `tide-siege`／`smoke-screen`；第 5 關 `tide-siege+hollow-ground`、`tide-siege+sluice-jam`、`smoke-screen+hollow-ground`、`smoke-screen+sluice-jam`。
- **加權勝率**：同一關所有（情境, 牌組）格等權平均。
- **`difficulty_index`（`p10-di-2`）**：`0.35×(1−planner) + 0.25×(1−forecast-aware) + 0.25×(1−one_mistake_recovery) + 0.15×planner 勝局平均回合比例`。勝局回合比例以 planner 勝場數加權。缺任一成分時不計算（回 `null`），避免殘缺數字被當成排序。報告另附 `difficulty_index_p10_di_1`（以新語意失誤的無條件勝率代入舊公式）僅供對照。
- **one_mistake_recovery_rate（`p10-di-2`）**：同（關卡, 牌組, 情境, seed）配對；`recoveries_after_mistake ／ eligible_mistake_games`，逐關合併。只要求 `planner-one-mistake` 時，報告仍在內部跑 planner 基準以完成配對。
- **合格失誤**：語義簽章 `type|skill_id|target|fixed` 與最佳不同，且 planner 分數嚴格較低；依排名取第一個。
- **破綻浪費**：被逾時吃掉、用在核心傷害為 0（全被護盾吸收）的攻擊上，或到結束仍未使用。

## 觀察（供 P10-1 之後參考，本包不據此改任何數值）

1. 關卡的相對難度主要由 forecast-aware 拉開（98.7 → 77.4 → 90.2 → 74.2 → 80.4%）；planner 在每一關都 ≥ 93.8%，分辨力很低。
2. 在關鍵窗口犯一次**真正的**錯（P10-0.1 語意），配對恢復率仍有 92.2～99.6%。現行關卡錯一次的代價極小，這是第 3 項指標全面超標的直接原因。
3. 第 3、5 關的 planner 勝局回合比例（約 0.71～0.73）比其他關低，表示這兩關可以提早打完——和它們 difficulty_index 偏低一致。

## 規格偏差與決策

- **solver 未實作**，依 P10 §5 允許列為 P10-1 前置。報告 `meta.solver` 明寫「planner 結果不是可解性證明」，任何文件都沒有以 planner 冒充可解性。
- **one_mistake_recovery_rate**：P10-0 採無條件勝率；P10-0.1 依派工改為同 seed 配對的條件恢復率並升 `p10-di-2`（見上方修正段）。逐關合併（pooled）而非各格等權，因為恢復率分母因格而異、可能為 0。
- **失誤窗口只有一個**：窗口找不到合格失誤時不往後延，直接記 `no_eligible_mistake`，讓每局的量測點可重現。本次全量 81,000 局實際都找得到合格失誤。
- **勝局回合比例**計畫未指明用哪個策略；本包使用 planner 勝局。
- **失誤窗口**用「第 2 回合起第一個可打斷預告；沒有就過半回合」，只讀玩家可見的預告。
- **完整 JSON 與 full 逐局失誤 CSV 未提交**（2.5 MB／16 MB）；提交的是逐格 CSV、省略逐格的摘要 JSON，以及 quick 的逐局失誤 CSV。完整檔可用上面的命令重建，SHA-256 可比對。
- `game:simulate` 與 `StrategyMatrixTest` 沒有改成新情境；它們仍是既有門檻，新的難度契約測試屬 P10-7。

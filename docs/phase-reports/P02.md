### 資源 URL 的取得方式

沒有沿用舊報告的推測網址，也沒有解析資料集 HTML 頁面。三個 resource URL 由 `https://data.gov.tw/api/v2/rest/dataset/{id}` 的 `distribution` 欄位取得（2026-09-08）：

| 資料集 | 主機 | 實際下載網址 |
|---|---|---|
| 45501 | `opendata.wra.gov.tw` | `/api/v2/2be9044c-6e44-4856-aad5-dd108c2e6679?sort=_importdate%20asc&format=JSON` |
| 41280 | `mas.nstc.gov.tw` | `/OPENDATA/GetFile?format=csv&serialno=381&fileodr=2` |

網址寫在 `config/opendata.php`，程式不拼湊 URL、不自創縣市篩選參數。

### 三個 adapter

`app/Services/OpenData/Adapters/`：`ReservoirConditionsAdapter`、`ScienceParkWaterAdapter`、`LandUseAdapter`。抓取與正規化分離（`fetch()` / `normalize()`），讓正規化可以用固定 fixture 直接測，不必依賴上游。

實際樣本欄位、單位、行政區／水庫代碼與觀測期間全部記在 [資料契約](../DATA-CONTRACT.md)。重點決策：

- **不推算蓄水率。** 45501 的 payload 只有 `effectivewaterstoragecapacity`，沒有滿水位容量，也沒有上游說明提到的蓄水百分比欄位。改用同一水庫、同一欄位的自我比較 `storage_index = 最新值 ÷ 24 小時視窗中位數`，樣本不足 6 筆就留 `null`。每次正規化都附 `storage_percentage_unavailable` 警告。
- **永和山水庫不是新竹縣的水庫。** 代碼對照表逐座記 `county` 與 `relation`（`located_in_hsinchu_county` / `supplies_hsinchu_area`）。
- **竹南、龍潭、銅鑼、宜蘭園區不是新竹行政區。** 逐園區記 `in_hsinchu`。
- **國土利用的分母是調查自身的互斥分類加總**，不引用外部總面積；`administrative_codes_available` 固定 `false`，因為 CSV 只有名稱沒有代碼。
- **公園綠地廣場是綠地配置的代理指標**，附 `not_a_heat_measurement` 警告，不是熱島量測。
- 缺值與零值分開：`0` 有效，空字串／`--`／`N/A` 轉 `null` 並記警告，不進分母、不進中位數。

### 標準化資料契約與快照

`NormalizedSnapshot`（`schema_version 1.0.0`）含 `snapshot_id`、`source_id`、`resource_url`、`fetched_at`、`observed_at` 或 `period`、`content_hash`、`quality`、`quality_reason`、`scope`、`metrics`、`units`、`warnings`、`byte_size`。時間一律存 UTC，民國年換算成西元並在 `period.calendar` 標 `roc`。

`data_snapshots` 資料表只存正規化結果。實測壓縮效果：

| source_id | 上游原始 | 儲存 payload |
|---|---|---|
| `wra.reservoir_conditions` | 282,788 bytes | 2,266 bytes |
| `nstc.science_park_water` | 818 bytes | 3,290 bytes |
| `moi.land_use` | 155,896 bytes | 5,689 bytes |

發布是原子的：抓取與清洗在交易外，交易內先把同來源舊列 `is_current` 關掉再插入新列。

### 傳輸防護

`GuardedDownloader` 提供固定 UA、TLS 驗證不可關閉、連線逾時 5 秒、單來源總預算 60 秒（含重試）、最多 3 次嘗試（只重試 429／5xx／連線失敗）、串流讀取的位元組上限、重新導向主機白名單、Content-Type 允許清單，以及「HTTP 200 但內容以 `<` 開頭」的假成功偵測。

### 快照與備援 fixture

- 示範情境：`database/fixtures/opendata/{source}.demo.json`，三個來源各一份，`quality` 固定 `demo`，`scope.fixture_version` 標版本，數值是人工中性值。`FixtureRepository` 拒絕載入 `quality` 不是 `demo` 的檔案。
- 上游樣本：`tests/Fixtures/OpenData/`，三份真實回應的裁切版，供正規化測試使用。
- `SnapshotResolver` 開局時解析「目前有效快照 → 示範情境」，回傳的 `snapshot_id` 由對局凍結；`containsDemoData()` 供 UI 決定是否顯示「示範情境」。

### 排程與命令

`routes/console.php` 三條排程走 `withoutOverlapping`，Hostinger 只需一條 cron 呼叫 `schedule:run`：

```text
0  *  * * *   opendata:refresh --schedule=hourly    # 水庫水情
10 4  * * *   opendata:refresh --schedule=daily     # 園區用水
40 4  * * 1   opendata:refresh --schedule=weekly    # 國土利用
```

另有 `opendata:refresh`（可指定 `--source`／`--schedule`／`--prune`）與 `opendata:status`。

## 自我驗收與修正

交付後重讀程式做了一次驗收，找到三項實際缺陷並修正，各補回歸測試。

### 1. 落後水庫的觀測被靜默丟棄（嚴重）

原本觀測視窗錨定在**全體**水庫的最新觀測時間。上游各水庫管理單位上傳頻率不同，只要一座落後超過 24 小時，它的觀測就整批落在視窗外。

重現（10405 觀測到 09-07 22:00、10501 只到 09-04 22:00，各 8 筆）：

```text
修正前  snapshot quality : fresh
        10501 永和山水庫 observed=NULL samples=0 storage=NULL index=NULL
        warnings: storage_percentage_unavailable
```

8 筆完好的觀測變成 `null`，而且**沒有任何警告**，快照還標成 `fresh`。這正是規格禁止的「用新資料掩蓋舊資料」。

修正：視窗改為錨定每座水庫自己的最新觀測；快照的 `observed_at` 改取追蹤水庫中**最舊**的那筆最新觀測；個別水庫落後另發 `reservoir_observation_stale` 警告點名。

```text
修正後  snapshot quality : stale
        10501 永和山水庫 observed='2026-09-04T14:00:00+00:00' samples=8 storage=2960.0 index=1.0012
        warnings: reservoir_observation_stale, storage_percentage_unavailable
```

回歸測試：`test_it_windows_each_reservoir_against_its_own_latest_observation`、`test_a_lagging_reservoir_makes_the_whole_snapshot_stale_and_is_named`、`test_it_warns_when_a_tracked_reservoir_is_absent_upstream`。

### 2. `prune()` 可能刪掉生效中的快照

排序依 `fetched_at desc`，時鐘誤差或補寫舊資料時，`is_current` 的那筆可能被排到保留範圍外而刪除，來源就會變成沒有快照。修正：加上 `where('is_current', false)`，並在沒有任何列時提早回傳 0（避免 `whereNotIn` 空集合退化成全刪）。

回歸測試：`test_pruning_never_deletes_the_current_snapshot`、`test_pruning_a_source_with_no_snapshots_deletes_nothing`。

### 3. CSV 欄數不符的資料列被靜默略過

`CsvTable` 直接 `continue` 掉欄數與標題不符的列。國土利用還有 `township_count_mismatch` 會間接抓到，園區用水則完全無感——少一個園區不會有任何跡象。修正：`CsvTable` 記錄 `skippedRows`，兩個 CSV adapter 都發 `malformed_rows_skipped` 警告。

回歸測試：`test_it_warns_instead_of_silently_dropping_a_malformed_row`。

## 規格偏差與決策

1. **不輸出蓄水百分比。** 技術規格 §4 已預留「沒有足夠欄位就使用有明列公式的情境指標」，本階段確認欄位確實不足，改用 `storage_index`。影響：P03 的水系情境修正要以相對指標而非蓄水率設計。
2. **年度統計不套 48 小時 stale 門檻。** 技術規格 §4.2 要求 P02 填明門檻，本階段定為：園區用水落後 > 1 個民國年、國土利用落後 > 2 個民國年。
3. **新增 `opendata:status` 命令。** 技術規格 §6 列有 `GET /api/v1/data-status`，但 HTTP 契約屬於 P03；本階段只做資料層的狀態輸出，沒有新增路由。
4. **`prune()` 預設不執行。** 技術規格 §5 要求清理不可破壞重播；`runs` 表在 P03 才建立，因此保留方法但不排程，並在契約與程式註解寫明 P03 必須加入引用保護。
5. **`mas.nstc.gov.tw` 的 UA 行為與舊報告不同。** 2026-09-07 盤點記載預設 curl UA 被擋 403；2026-09-08 本機以 `curl/8.8.0` 與專案 UA 實測都是 HTTP 200。已在資料契約更正措辭，仍保留固定 UA 與 403 的受控失敗處理，不宣稱必須偽裝瀏覽器。
